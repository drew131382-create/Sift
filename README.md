# Sift

在设备本机整理截图。最低 iOS 17；真实模型推理需要支持 Metal 的 iPhone。模拟器可验证界面与注入的流程，不能代替真机模型验收。

## 运行与模型

GitHub 仓库保存源代码、工程配置、模型清单、分词器、许可和开发文档。模型权重 `model.safetensors` 通过 [模型 Release](https://github.com/drew131382-create/Sift/releases/tag/model-qwen3-0.6b-sift-2026-10-04) 附件分发，不随 Git 提交；真实截图、个人截图标注、构建产物及签名凭证保留在本地。新克隆的工程需先补齐模型权重，才能通过构建前的模型校验；仓库不含可直接安装的应用包。

### 从公开仓库开始

准备 Git、GitHub CLI、Python 3 和 Xcode，在终端执行：

```sh
git clone https://github.com/drew131382-create/Sift.git
cd Sift
gh release download model-qwen3-0.6b-sift-2026-10-04 \
  --repo drew131382-create/Sift \
  --pattern model.safetensors \
  --dir Sift/Resources/LocalModel
python3 Scripts/prepare_local_model.py --verify-only
open Sift.xcodeproj
```

也可从上述 Release 页面下载 `model.safetensors`，放入 `Sift/Resources/LocalModel/`，然后执行校验。下载仅用于开发者准备安装包，应用运行时不下载模型。

打开 `Sift.xcodeproj`，选择 Sift scheme。真机需要有效的 Apple 开发签名。工程配置来自 `project.yml`，修改后执行 `xcodegen generate`。

- MLX Swift LM 固定 **3.32.3**；当前内置 **Qwen3 0.6B · Sift 微调**（4-bit QLoRA 融合权重），身份 `local/Sift-Qwen3-0.6B-QLoRA`，权重 SHA-256 / 修订 **7252e5c48ad95c76ed8900027d4df16f49a588ef966d1cef654b6af6db1e5a5a**。基于官方 `Qwen/Qwen3-0.6B-MLX-4bit` 修订 `173234aa840d113125e9f2271100ddbaf16c9620`，不是官方发布的训练版本。
- 模型、分词器和清单位于 `Sift/Resources/LocalModel`，约 **333 MB**，随应用安装；实际应用包更大。LFM2.5 与 VLM 实验资源保留在项目外，不同时打包。
- 开发者准备资源：`python3 Scripts/prepare_local_model.py --source /path/to/candidate-model-v2`。只复制和校验固定的本地微调产物，无模型下载。原版对照可显式使用 `--profile qwen0.6 --output /path/outside/project`，禁止写回应用模型目录。
- 构建前自动执行 `--verify-only`，离线检查资源完整性。应用首次加载也校验本地文件，运行期间不调用下载器或云端模型。
- `Sift/Resources/Licenses` 保留 Qwen Apache-2.0 与依赖许可、NOTICE；LFM 实验许可随实验权重保存在项目外。

## 识别流程

Vision 中英文 OCR → 版面和字段候选 → 明确场景直接提取 / 复杂场景本地 Qwen 判断用途与安排性质 → 本地关联字段与原文核验 → 保存卡片或跳过。

扫描、导入、重试和恢复统一使用 `SemanticExtracting.evaluate(document:)`。模型只返回业务类别和安排性质；本地代码关联主体、原文证据与字段，不让模型选择字段编号或生成标题、金额和时间，数字始终从原文复制。实付与参考价分开，付款疑问、原价优惠余额不冒充实付；日程必须有明确安排依据。当前采用宽松收录：商品选购、比价、酒店选房、菜单、公开活动，以及有可读实际内容的短视频、广告、评论、新闻等可归收藏；真实聊天界面中有多条对话消息的截图归入“闲聊”，通用评论输入框不证明聊天。社交平台分享的他人票券不能建立本人的日程。字段缺失或冲突时保留已核验的信息，在详情提示，不补猜值。成功 OCR 后无文字或只有可确定的界面噪声正常跳过；读取、OCR 执行、模型输出和原文核验异常保留可重试任务，不建空卡。直接提取无法核验时交给模型继续判断，聊天文字按段合并，不因文字块数量超过字段上限而直接失败。

复杂路径仅使用完整OCR文字、阅读顺序与业务区域，模型不接收图片。普通截图一次分类，超长正文按实际token预算分段覆盖，保留短主体和安排上下文；每次输入最多2048，输出最多192 tokens。整张截图采用30秒协作超时目标，初始化与打包可能超过目标，不能当作严格实时期限。模型延迟加载，批次结束、内存警告或空闲30秒释放，无运行时下载或云端接口。遗留瞬时图片属性不编码入OCR或卡片，当前流程不再填充。

卡片保留原文时间、金额单位与货币，详情展示字段来源、识别提示和多个独立订单/场次。规则只用于之后主动扫描、导入或重试，历史卡片和用户修改继续保留。

## 识别结果直接展示与重新处理

场景和原文校验通过的信息卡直接进入首页，无需人工确认；当前不因缺少可选字段或普通识别提示阻挡展示。识别失败任务在信息库的“重新处理”中展示，正在重新识别或失败任务对应的旧卡暂时隐藏。可选的 `ReprocessingReason` 保留历史兼容，用户修改继续保存。

多段摘录、步骤、链接及参考路线是互补内容，不按单值冲突隐藏；普通正文不因某段OCR分数偏低阻挡展示。已关联原文的门店文字使用较宽门槛，号码、实付及日程时间仍保持检查。打开新版时重新检查旧正文误报，无需再次扫描。修正记录见 [正文展示修正](Evaluation/results/2026-10-07-excerpt-admission-fix.md)。

信息库顶部的“重新处理”入口按截图合并不完整卡片与任务，支持查看原图、重新识别和编辑。补全保存后自动检查，通过即恢复展示；重试使用已有本地副本并保留用户修改。失败不记作无关；已存在卡片重新识别后未确认有效内容时保留原信息及失败任务。旧已完成、归档状态保留，不自动启动重新识别。

取餐优先显示原文对应的商家和号码。统一门店解析支持标签、跨块名称、订单店名及短信署名，不要求名称含“店”；有明确分店则保留。同一业务区域内关联，平台、菜品、广告和地图地点不充当商家。当前不因店名缺失阻挡已识别内容展示；无法确定时留空，不根据品牌常识补写。

## 界面与扫描

界面采用黑白黄与轻拟物纸张质感，视觉规范和本地预览见 [Design/README.md](Design/README.md)。

- 五组按固定顺序展示：取货码 / 取件码；日程 / 预约 / 出行；消费 / 订单 / 凭证；资料 / 地点 / 灵感收藏；闲聊。
- 最新卡片加最多两层背板，组标题通过拟物抽出与回叠动画展开或收起；展开后卡片保留正间距。搜索、筛选直接展开匹配组，减少动态效果时使用短淡入淡出。隐藏卡片不接收点击或辅助功能焦点，移动中的卡片暂不响应点击。
- 历史健康卡归日程，历史聊天归闲聊，其他归收藏并显示“历史未分类”；保留原分类编码、字段与用户修改。
- 缩略图和文字详情入口分离。图片直接打开全屏本地原图，支持捏合缩放、双击、拖动、关闭；原图丢失不影响查看卡片文字。
- 扫描前选择本地日期范围，默认含今天的最近7天，支持最近30天和自定义日期；只读取元数据预览数量，点击开始才加载图片。
- 逐张扫描、有进度与停止；停止后当前一张结束，不读取下一张。所选批次先持久化截图元数据，暂停和重启后通过“继续”恢复同一批任务。
- iOS 26+、支持后台 GPU 的设备使用 `BGContinuedProcessingTask` 延续用户开始的扫描，并通过系统实时活动显示进度。需要启用 Background GPU Access 且描述文件包含对应 entitlement；系统拒绝、取消或内存不足时保存进度，不以普通后台时间运行 MLX。旧系统切到后台会暂停。
- 为支持锁屏中的已授权后台任务，本地数据采用 `completeUntilFirstUserAuthentication` 文件保护：重启后首次解锁前仍无法读取，首次解锁后锁屏可继续处理。识别继续完全离线。
- 无关截图删除临时副本，不保存信息卡或 OCR原文，只留下资源标识、修改时间、指纹和模型/提示词/校验版本用于去重。
- 仅读取本地可用照片。iCloud独有图片提示先在系统相册下载，再重试；有限权限数量只涵盖授权截图。
- 设置可启用自动识别，打开 Sift 或应用在前台发现相册变化时，只更新最近 7、30 或 90 天内尚未处理的截图。已开始的扫描在系统授权时可以转到后台继续；应用挂起或退出时，新截图会在下次打开 Sift 后检查。超期内容只从 Sift 移除，iPhone「照片」原图保留。
- 自动识别默认关闭；开启后按所选天数滚动保留和处理截图，窗口外的 Sift 卡片、本地图片、任务及去重记录会清理。手动导入且没有照片资源标识的图片不受这个期限影响。
- SQLite存储、FTS5搜索、字段编辑、本地提醒、用户主动打开地图或添加日历继续保留。

## 验证状态

LFM2.5 对照未达到可用标准，已按用户选择恢复 Qwen3-0.6B，保持场景判断与原文字段关联分工。两模型结果见 [模型对照报告](Evaluation/results/2026-10-04-lfm-comparison-report.md)。当前 Qwen 路线见 [技术路线调整报告](Evaluation/results/2026-10-04-scene-report.md)，[VLM对照](Evaluation/results/2026-10-03-vlm-report.md) 和 [旧字段选择结果](Evaluation/results/2026-10-03-grounded-report.md) 仅作为历史基线。模拟器覆盖规则、扫描状态和界面；Mac 运行真实模型与 Vision。159 张固定回归图为助手标注，数字字段标注不完整，不能作为人工独立准确率验收。

2026-10-04 按用户“同批样本比原版更准确就替换”的要求，已将第 240 步微调融合权重设为应用默认模型。44 张开发留出样本上的完整校验流程正确数由 31/44（70.5%）提高到 34/44（77.3%）。这些样本以前已观察，不是独立验收；分类收益不能代替数字字段验收。报告见 [Qwen 微调报告](Evaluation/results/2026-10-04-qwen-finetune-report.md)，构建和安装状态见 [部署记录](Evaluation/results/2026-10-04-qwen-finetune-deployment.md)。

2026-10-08 修复空 OCR 和聊天字段超限导致的处理失败。四张手机真实原图的开发回归中，群聊收录、无文字照片跳过、票券分享进入收藏；评论页仍被模型判为无关，存在漏收。此轮结果为 3/4，不代表整体准确率达标。模拟器和真机构建通过，手机已更新至构建号 `2026100801`；安装成功不等同于真机推理验收。详见 [处理失败修复记录](Evaluation/results/2026-10-08-processing-failure-fix.md)。

测试和标注格式见 [Evaluation/README.md](Evaluation/README.md)。保留旧模型和旧日程评测结果，不能把它们视为当前版本成绩。飞行模式、真机热机耗时、整个进程内存及发热仍需独立验证。

标准工程保留后台 GPU entitlement。现有手机描述文件缺少该授权时，可构建明确标记的前台版本：覆盖 `SIFT_ENTITLEMENTS_PATH=Sift/SiftForeground.entitlements SIFT_BACKGROUND_GPU_ENABLED=false`。此版本禁止后台 GPU 工作，切到后台保存进度、回到前台继续；相同 bundle ID 更新保留用户数据。不能将前台版本当作已完成后台 GPU 验收。

## 数据边界

核心识别无内容上传接口，无网络模型兜底。用户主动打开地图、网页、系统日历，以及系统设备备份由各自服务和设备设置管理。文件保护不是独立数据库加密，也不代表禁止系统备份。
