# Sift

在设备本机整理截图。最低 iOS 17；真实模型推理需要支持 Metal 的 iPhone。模拟器可验证界面与注入的流程，不能代替真机模型验收。

## 运行与模型

GitHub 仓库保存源代码、工程配置、模型清单、分词器、许可和开发文档。模型权重 `model.safetensors`、真实截图、个人截图标注、构建产物及签名凭证留在本地，不随 Git 提交。新克隆的工程须先通过下方 `--source` 命令准备微调产物，才能通过构建前的模型校验；仓库不含可直接安装的应用包。

打开 `Sift.xcodeproj`，选择 Sift scheme。真机需要有效的 Apple 开发签名。工程配置来自 `project.yml`，修改后执行 `xcodegen generate`。

- MLX Swift LM 固定 **3.32.3**；当前内置 **Qwen3 0.6B · Sift 微调**（4-bit QLoRA 融合权重），身份 `local/Sift-Qwen3-0.6B-QLoRA`，权重 SHA-256 / 修订 **7252e5c48ad95c76ed8900027d4df16f49a588ef966d1cef654b6af6db1e5a5a**。基于官方 `Qwen/Qwen3-0.6B-MLX-4bit` 修订 `173234aa840d113125e9f2271100ddbaf16c9620`，不是官方发布的训练版本。
- 模型、分词器和清单位于 `Sift/Resources/LocalModel`，约 **333 MB**，随应用安装；实际应用包更大。LFM2.5 与 VLM 实验资源保留在项目外，不同时打包。
- 开发者准备资源：`python3 Scripts/prepare_local_model.py --source /path/to/candidate-model-v2`。只复制和校验固定的本地微调产物，无模型下载。原版对照可显式使用 `--profile qwen0.6 --output /path/outside/project`，禁止写回应用模型目录。
- 构建前自动执行 `--verify-only`，离线检查资源完整性。应用首次加载也校验本地文件，运行期间不调用下载器或云端模型。
- `Sift/Resources/Licenses` 保留 Qwen Apache-2.0 与依赖许可、NOTICE；LFM 实验许可随实验权重保存在项目外。

## 识别流程

Vision 中英文 OCR → 版面和字段候选 → 明确场景直接提取 / 复杂场景本地 Qwen 判断用途与安排性质 → 本地关联字段与原文核验 → 保存卡片或跳过。

扫描、导入、重试和恢复统一使用 `SemanticExtracting.evaluate(document:)`。模型只返回业务类别和安排性质；本地代码关联主体、原文证据与字段，不让模型选择字段编号或生成标题、金额和时间，数字始终从原文复制。实付与参考价分开，付款疑问、原价优惠余额不冒充实付；日程必须有明确安排依据。具有明确主体和完整可用信息的商品选购、比价、酒店选房、菜单和公开活动归收藏；普通短视频、广告口号、评论、闲聊、个人主页和新闻不因出现主题或长文字而收录。目标明确但关键字段缺失或冲突时待确认；空白/输出异常/模型明确不确定保留可重试失败，不建空卡。已解析但缺业务依据的分类仅在确定的无关反例中跳过，其他情况继续支持重试。

复杂路径仅使用完整OCR文字、阅读顺序与业务区域，模型不接收图片。普通截图一次分类，超长正文按实际token预算分段覆盖，保留短主体和安排上下文；每次输入最多2048，输出最多192 tokens。整张截图采用30秒协作超时目标，初始化与打包可能超过目标，不能当作严格实时期限。模型延迟加载，批次结束、内存警告或空闲30秒释放，无运行时下载或云端接口。遗留瞬时图片属性不编码入OCR或卡片，当前流程不再填充。

卡片保留原文时间、金额单位与货币，详情展示字段来源、待确认原因和多个独立订单/场次。规则只用于之后主动扫描、导入或重试，历史卡片和用户修改继续保留。

## 展示前核对

首页只展示通过保守准入或人工确认的待处理卡片。自动准入要求：单一场景能通过本地明确场景提取独立核验、标题对应原文主体、关键字段齐全且唯一、无缺失或冲突提示；每个字段必须有可追溯 OCR 来源。号码、金额、时间和凭证编号的 OCR 清晰度门槛为 0.95，其余字段为 0.90。门槛是保守工程设置，尚非经过校准的正确率，也不保证零错误。

模型或混合路径产生的有用信息先进入“待确认”；无关截图继续跳过，识别失败继续在处理任务中重试。用户可查看原图、修改分类和字段，“保存修改，稍后确认”保留草稿，“确认并加入首页”明确批准整张卡片及同图其他事项。旧待处理卡片没有展示批准记录时在待确认中显示，历史内容与用户修改不删除；已完成、归档的历史状态保留。批准状态随本地卡片保存；重复识别仅在原图指纹和 OCR 原文均未变化时保留人工批准。

## 界面与扫描

界面采用黑白黄与轻拟物纸张质感，视觉规范和本地预览见 [Design/README.md](Design/README.md)。

- 四组按固定顺序展示：取货码 / 取件码；日程 / 预约 / 出行；消费 / 订单 / 凭证；资料 / 地点 / 灵感收藏。
- 最新卡片加最多两层背板，组标题展开或收起；搜索、筛选自动展开匹配组。隐藏卡片不接收点击或辅助功能焦点。
- 历史健康卡归日程，历史聊天、其他归收藏并显示“历史未分类”；保留原分类编码、字段与用户修改。
- 缩略图和文字详情入口分离。图片直接打开全屏本地原图，支持捏合缩放、双击、拖动、关闭；原图丢失不影响查看卡片文字。
- 扫描前选择本地日期范围，默认含今天的最近7天，支持最近30天和自定义日期；只读取元数据预览数量，点击开始才加载图片。
- 逐张扫描、有进度与停止；停止后当前一张结束，不读取下一张。所选批次先持久化截图元数据，暂停和重启后通过“继续”恢复同一批任务。
- iOS 26+、支持后台 GPU 的设备使用 `BGContinuedProcessingTask` 延续用户开始的扫描，并通过系统实时活动显示进度。需要启用 Background GPU Access 且描述文件包含对应 entitlement；系统拒绝、取消或内存不足时保存进度，不以普通后台时间运行 MLX。旧系统切到后台会暂停。
- 为支持锁屏中的已授权后台任务，本地数据采用 `completeUntilFirstUserAuthentication` 文件保护：重启后首次解锁前仍无法读取，首次解锁后锁屏可继续处理。识别继续完全离线。
- 无关截图删除临时副本，不保存信息卡或 OCR原文，只留下资源标识、修改时间、指纹和模型/提示词/校验版本用于去重。
- 仅读取本地可用照片。iCloud独有图片提示先在系统相册下载，再重试；有限权限数量只涵盖授权截图。
- SQLite存储、FTS5搜索、字段编辑、本地提醒、用户主动打开地图或添加日历继续保留。

## 验证状态

LFM2.5 对照未达到可用标准，已按用户选择恢复 Qwen3-0.6B，保持场景判断与原文字段关联分工。两模型结果见 [模型对照报告](Evaluation/results/2026-10-04-lfm-comparison-report.md)。当前 Qwen 路线见 [技术路线调整报告](Evaluation/results/2026-10-04-scene-report.md)，[VLM对照](Evaluation/results/2026-10-03-vlm-report.md) 和 [旧字段选择结果](Evaluation/results/2026-10-03-grounded-report.md) 仅作为历史基线。模拟器覆盖规则、扫描状态和界面；Mac 运行真实模型与 Vision。159 张固定回归图为助手标注，数字字段标注不完整，不能作为人工独立准确率验收。

2026-10-04 按用户“同批样本比原版更准确就替换”的要求，已将第 240 步微调融合权重设为应用默认模型。44 张开发留出样本上的完整校验流程正确数由 31/44（70.5%）提高到 34/44（77.3%）。这些样本以前已观察，不是独立验收；分类收益不能代替数字字段验收。仍保留严格首页准入、字段核验及人工确认。报告见 [Qwen 微调报告](Evaluation/results/2026-10-04-qwen-finetune-report.md)，构建和安装状态见 [部署记录](Evaluation/results/2026-10-04-qwen-finetune-deployment.md)。

测试和标注格式见 [Evaluation/README.md](Evaluation/README.md)。保留旧模型和旧日程评测结果，不能把它们视为当前版本成绩。飞行模式、真机热机耗时、整个进程内存及发热仍需独立验证。

标准工程保留后台 GPU entitlement。现有手机描述文件缺少该授权时，可构建明确标记的前台版本：覆盖 `SIFT_ENTITLEMENTS_PATH=Sift/SiftForeground.entitlements SIFT_BACKGROUND_GPU_ENABLED=false`。此版本禁止后台 GPU 工作，切到后台保存进度、回到前台继续；相同 bundle ID 更新保留用户数据。不能将前台版本当作已完成后台 GPU 验收。

## 数据边界

核心识别无内容上传接口，无网络模型兜底。用户主动打开地图、网页、系统日历，以及系统设备备份由各自服务和设备设置管理。文件保护不是独立数据库加密，也不代表禁止系统备份。
